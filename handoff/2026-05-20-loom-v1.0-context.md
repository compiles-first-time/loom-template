## The collaboration model

**Nick is the Architect. Claude is the Builder.** This is from Loom's L1 skeleton (spec-as-codebase). The dataflow boundary:

- Architect: integrates external input (research, real-session findings, the user's own product instincts), produces handoffs (proposals, plans, decisions).
- Builder (you): operates on the filesystem, writes the code, runs the tests, files the PRs.

The user **proposes**; the Builder **implements**; the Builder **flags disagreements** before starting, not after.

### What "flag disagreements" looks like in practice

Every approved plan in this project has had a "Disagreements / scope changes" section before the PR sequence. Examples:

- v0.2 plan: 7 disagreements with the user's original proposal (Rule-22 schema is unachievable from a hook → split into mechanical/introspective subsets; event-log coverage as soft warning not hard fail; etc.).
- v0.3 plan: 7 disagreements (intent classifier is heuristic and brittle; pattern-based redaction at hook layer not just doctor; etc.).
- v0.4-v1.0 plan: 7 disagreements (12 starter specialists not 20; discovery gate on deploy not bootstrap; LR-04 as meta-rule subsuming LR-02 + LR-03; etc.).

Nick **expects** disagreements and accepts most of them. The pattern: lay out the plan, flag what you'd do differently with reasons, ask for the go-ahead, then execute. **Do not silently deviate from the plan once approved.**

## Nick's working style (observed across 4 batches)

These are explicit preferences, not assumptions:

1. **"One big go" for execution.** Once the plan is approved, cascade through PRs without pausing for per-PR confirmation. Nick reviews at the end.
2. **Cascade PR pattern.** Each PR branches off the previous one's tip. Nick merges them in order; later PRs auto-rebase against the new main.
3. **Regression testing along the way.** After every PR, smoke-test the new feature with a synthetic input. Note bugs found + fixes in the PR description.
4. **Honest about scope.** If a feature can't be fully delivered, say so explicitly. The L6 "Langfuse / OTel are integration targets, not shipped" reframe is a direct example.
5. **Citations on every load-bearing claim.** Provenance tags `[source][confidence]`. Per LR-05: every architectural decision is **best-current-call until superseded by independent peer-reviewed evidence**. Each ADR has an `Evidence basis` section.
6. **Interoperability tracking.** Every v0.4+ ADR has bidirectional `Affects / Affected by` links. `loom doctor`'s `bidirectional-adr-links` check verifies the back-references.
7. **`Justifications` column** (renamed from "Why" in the user-supplied xlsx). Used in every specialist SKILL.md failure-modes table + risk-register.md.
8. **Constitution-as-text.** The kernel is text. Specialists are proposed; the user decides; the user approves. Never auto-apply structural changes. This is Kernel Rule 8 (anti-paternalism) made operational.
9. **No auto-merge.** Builder opens PRs; user merges them via GitHub. `gh pr merge` from the Builder is disallowed by the auto-mode classifier (this has been tested — the system blocks it).
10. **Markdown link syntax for file refs.** Per the VSCode extension context: `[filename.ts](src/filename.ts)` or `[filename.ts:42](src/filename.ts#L42)`. Don't use backticks for files.
11. **Smoke artifacts cleaned before commit.** When you run a bootstrap or discover script that produces files during testing, `git checkout HEAD -- <file>` or `rm` the artifacts so the template stays generic.
12. **Each PR description includes a `Test plan` section.** Pre-flight checks the Builder ran (with ✓) + a `[ ] Reviewer:` line for the user to manually verify.

## Critical decisions and idioms (the nuances)

This section captures the *why* behind decisions that would not be obvious from reading the code or ADRs in isolation.

### Constitution-as-text

Loom never auto-applies structural changes. Every proposal — skeleton amendment, lesson promotion, ADR change — is a markdown artifact the user reads + approves before anything is touched. This is the operational form of Kernel Rule 8 (anti-paternalism). Even when the Builder *could* mechanically apply a change, it shouldn't.

### Hooks are transparency, not blocking

PreToolUse, PostToolUse, Stop, SessionStart, UserPromptSubmit hooks emit events to the JSONL log but never block tool calls. Real enforcement (refusing to deploy without a discovery gate) lives in the *user-facing scripts* (`deploy.sh` Step 0/5), not in the hooks. Rationale: false positives at hook level destroy trust; the audit trail is the load-bearing artifact.

### Rule-22 mechanical / introspective split (ADR-0011)

The v0.1 spec listed a single Rule-22 trace schema with `confidence`, `what_would_raise_to_95`, `decision_log`, `constitutional_check`. A hook running on `PreToolUse` has access to the tool name + args but **no access to the model's reasoning**. The v0.2 split:

- **Mechanical fields** (hook-emitted, always-on): timestamp, session_id, cwd, event_type, tool, tool_args_summary, exit_code, error_signature, kernel_version, loom_version.
- **Introspective fields** (LLM-emitted by convention via `event_type: claim` records): confidence, what_would_raise_to_95, sources, decision_log, constitutional_check.

The combined log is Rule-22 compliant *in spirit*; the split is honest about what each emitter can fill.

### Magentic-One pattern, session is the supervisor

The v0.1 spec implied a separate "Magentic-One supervisor" process. v0.2 reframes: **the Claude Code session itself is the supervisor**. Magentic-One stays as the cited *pattern* (Fourney et al. 2024); the *implementation* is the session + hooks + subagents. The two-ledger pattern (Task Ledger + Progress Ledger) is operated by hooks (Session log) + HR work-graph (v1.0 R).

### Critic + Constitution-Service are read-only on every path (ADR-0012)

Both subagents have `tools: Read, Glob, Grep` — no Edit, no Write. Audit writes happen via hooks, not from the subagents. This removes a self-modification risk class by construction: the constitution validator never has an edit path into the constitution.

### LR-04 subsumes LR-02 + LR-03 (per ADR-0027 / v0.6 P)

LR-02 (production mutations) and LR-03 (secrets in args) both apply to overlapping cases (`vercel env add SUPABASE_SERVICE_ROLE_KEY xxx` triggers both). v0.6 introduces LR-04 as the **meta-rule** that classifies tool calls into three categories (`external_service_setup`, `destructive_actions`, `credentials`); LR-02 + LR-03 become specializations. **They're kept as historical records** because the `production_mutation_attempted` event keeps firing for back-compat with consumers that grep for it.

### Discovery gates on **deploy**, not **bootstrap** (per ADR-0026 / v0.5 O)

Original v0.4 plan blocked bootstrap until discovery was filled. Nick pushed back: the skeleton may be rebuilt as discovery deepens; users can't reasonably discover before seeing the scaffold. v0.5 ties the gate to `scripts/deploy.sh` Step 0/5 instead. Deploying without a risk register is the genuinely dangerous case; bootstrap is harmless.

### JSON-canonical + markdown-mirrored work-graph (per ADR-0029 / v1.0 R)

Markdown tables don't render DAGs cleanly past ~20 nodes. v1.0's work-graph lives at `orchestration/work-graph.json` (canonical) + `orchestration/task-ledger.md` (regenerated mirror for human readability). HR consumes the JSON; humans read the markdown.

### Bundled registry vs project-local override (per ADR-0023 / v0.4 L)

Two namespaces:

- `agents/specialists/_registry/<name>/SKILL.md` — **bundled** with Loom; updated via template upgrades.
- `agents/specialists/<name>/SKILL.md` — **project-local**; may override the bundled version by setting `extends: _registry/<name>` in frontmatter.

Override semantics are **shallow** — project-local fields win; bundled fields fill the rest.

### `Justifications` column rename (user direction 2026-05-20)

The Credit Validation xlsx that established the failure-modes register format has a "Why" column. Nick renamed it to **`Justifications`** to be clearer. Every specialist SKILL.md failure-modes table + discovery risk-register.md uses `Justifications`.

### Subagent staleness sentinel + Anthropic upstream (per ADR-0020 / v0.3 J)

**Critical gotcha.** Claude Code builds the subagent registry at session start. Files added to `.claude/agents/` mid-session are invisible until restart. v0.3 J ships:

1. `.claude/agents/.last-discovered-at` — zero-byte sentinel; mtime tracks "we discovered these."
2. Bootstrap stamps the sentinel after stamping new subagent files + ends with a **"RESTART CLAUDE CODE NOW"** banner.
3. SessionStart hook auto-creates the sentinel on first run (fresh clones don't false-positive).

**Anthropic upstream issue.** ADR-0020 contains a draft GitHub issue for Anthropic requesting dynamic subagent registry reload. **Nick needs to file it from his account.** Until filed, every template upgrade requires users to restart Claude Code.

### Specialist failure-modes use xlsx convention (per ADR-0022)

Per the Credit Validation xlsx Nick supplied. Every specialist SKILL.md has a `## Failure modes` markdown table with columns: ID, Type (**SE** = System Exception / **BE** = Business Exception), Framework Location, Usecase, Assets/Cred, Input Source, Expected Input, Expected Output, Input Format, Output Format, Next Step, **Justifications**. The risk-register.md in `discovery/` follows the same format.

### Auto-classifier is heuristic, never authoritative

The intent classifier (ADR-0017), production-mutation detector (ADR-0017), permissions classifier (ADR-0027), OAuth-preference detector (ADR-0028), and skeleton-amendment proposer (ADR-0026) are all **heuristic**. Misclassifications are tolerable; the cost of getting it wrong is "extra context the model ignores." False negatives are caught by the Critic monthly audit + secrets-doctor retrospective scan.

### Memory: agent vs project

- **Project event log** at `memory/event-log/YYYY-MM-DD.jsonl` — gitignored; hooks write to it. Per-session JSONL.
- **Per-agent memory** at `agents/<name>/self-knowledge.md` — committed; the agent's personality/learning over time.
- **Claude Code memory** at `~/.claude/projects/<project-id>/memory/` — persistent across sessions in the same project dir; this is where the Builder writes user-profile / project-state notes per the system prompt's auto-memory directive.

### LF/CRLF warnings on Windows

Every `git add` on this Windows machine produces `LF will be replaced by CRLF` warnings. **Harmless.** Don't try to fix it by changing line endings — the warnings are git telling you it'll normalize on commit, which is the desired behavior.

## Established patterns

### PR cascade workflow

1. Branch off the previous PR's tip (e.g., PR-L → `v0.4/l-...` → PR-M branches off `v0.4/l-...`).
2. Implement; smoke-test; commit on the branch.
3. `git push -u origin <branch>` + `gh pr create --base main --head <branch>`.
4. Document `Test plan` in PR body with ✓ for what you ran + `[ ] Reviewer:` for what Nick should verify.
5. **Do not merge** — Nick merges via GitHub UI.

### ADR template (v0.4+)

Required sections (per `adr/0000-template.md`):

- **Context** — what problem are we solving
- **Decision** — what we decided
- **Evidence basis** — primary source(s), corroborating sources, what would change this call (per LR-05)
- **Consequences** — locks in, locks out, migration path
- **Alternatives considered**
- **Affects / Affected by** — bidirectional dependency tracking (per ADR-0022; `loom doctor` checks back-references)
- **References**

### Smoke testing pattern

After writing each script:

1. `node --check <file>` for syntax.
2. Synthetic input (e.g., `echo '{"...":..}' | node scripts/hooks/<hook>.mjs`) to verify end-to-end behavior.
3. Inspect the resulting JSONL log for the expected event.
4. **Clean up smoke artifacts** before commit (`git checkout HEAD -- <stamped-file>` or `rm -rf <smoke-output>`).

### YAML parser bugs that recur

We've written three narrow YAML parsers (`mcp-yaml-to-settings.mjs`, `registry-loader.mjs`, `permissions-classifier.mjs`). Each has had a similar bug:

1. **Inline comment stripping.** `enabled: false  # set to true` parsed as `"false  # set to true"` (string) instead of `false` (boolean). Fixed in all three; if you write a fourth, **strip inline `#` outside quotes before scalar parsing**.
2. **Escape sequences in double-quoted strings.** `"\\b(?:foo)\\b"` in YAML means literal `\b(?:foo)\b` after unescape (regex word boundaries). My parsers initially passed through `\\b` unchanged, breaking regex matching. Fixed by unescaping `\\` → `\` and preserving regex-meaningful escapes (`\b`, `\d`, etc.).

If you write a YAML parser, copy the helpers from `scripts/lib/registry-loader.mjs` (which has the most-tested implementation).

### Top-level await + const hoisting

Top-level `await main()` in a `.mjs` file runs **before** subsequent `const` declarations are reached. Bug encountered in `scripts/lib/discover.mjs`:

```javascript
await main();  // ← runs, references QUICK_QUESTIONS
async function main() { ... }
const QUICK_QUESTIONS = [...];  // ← not yet declared when main() runs
```

Fix: move `await main()` to the **bottom** of the file, after all module-level const declarations.

### Stale-read errors during long sessions

Mid-session, `Edit` and `Write` tools sometimes return `"File has been modified since read..."` even though the file content is unchanged. The system reminders that flag "intentionally modified" files often re-show the *current* file state, which can be confusing. Recovery: `Read` the file again to refresh the cached state, then retry the edit.

### Anthropic CLI auto-mode classifier

`gh pr merge` from the Builder is **blocked** by Anthropic's auto-mode classifier (with a reason: "Merging the agent's own PR to main contradicts the user's explicit instructions"). This is correct behavior; Nick merges PRs himself.

## Appendix A — glossary of project-specific terms

- **ADR** — Architecture Decision Record. Atomic unit of consequential decisions. Numbered `0001`–`NNNN`. Template at `adr/0000-template.md`.
- **LR** — Local Rule. Project-specific constitutional extension. Numbered `LR-01`–`LR-NN`. Defined in `constitution/local-rules.md`.
- **Base agent** — One of the six that ship with every Loom project (HR, EAC, Human-Replica, Critic, Memory-Keeper, Constitution-Service). Design source at `agents/<name>/SKILL.md`; runtime at `.claude/agents/<name>.md`.
- **Specialist** — A domain-bound agent created on demand. Bundled specialists live at `agents/specialists/_registry/<name>/`; project-local instances or overrides at `agents/specialists/<name>/`.
- **Registry** — `agents/specialists/_registry/manifest.yaml` plus the SKILL.md files; the source of truth for which specialists are available.
- **Work item / WI** — A unit in `orchestration/work-graph.json`. Each is `WI-FR-NN` (functional requirement) or `WI-NFR-<slug>` (NFR pillar).
- **Quick scan** — The 5-question discovery phase that runs at bootstrap (`scripts/discover.{sh,ps1} --quick`).
- **Full discovery** — The 30–60-minute walk-through producing `requirements.md` + `risk-register.md` + `open-questions.md`.
- **xlsx convention** — The failure-modes register format derived from the Credit Validation Excel file: SE/BE rows + Justifications column. Per ADR-0022.
- **Mechanical / introspective split** — The Rule-22 trace divided between hook-emittable fields (mechanical) and LLM-emittable fields (`event_type: claim`).
- **Cascade PR** — Each branch off the previous PR's tip; user merges in order.
- **Architect / Builder** — Nick / Claude division of labor.
- **Constitution-as-text** — The kernel + rules are markdown; enforcement is social + hook-based, never auto-apply.
- **Provenance tag** — `[source][confidence]` annotation on a non-trivial claim. Sources: `[base]`, `[LLM-A]`, `[LLM-B]`, `[kernel]`, `[transcript]`, `[consult-gov]`, `[consult-plat]`, `[primer]`, `[synth]`, `[research-p1]`, `[user-report]`, `[user-direction]`, `[vendor]`, `[primary]`, `[institutional]`, `[user-prior-work]`. Confidence: `[H]` (primary verified), `[M]` (corroborated), `[L]` (training-knowledge), `[S]` (speculative), `[V]` (vendor marketing — discount).
