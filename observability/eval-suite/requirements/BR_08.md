# BR_08 — `discovery-authored` doctor check (stamped ≠ authored)

> **Requirement source:** handoff 2026-07-15 "Pending work" #2 (Phase-1b reliability) + lesson [`2026-07-10-discovery-must-be-authored-not-stamped.md`](../../../lessons-learned/2026-07-10-discovery-must-be-authored-not-stamped.md). Extends [ADR-0015](../../../adr/0015-loom-doctor.md) (loom doctor); ties to [ADR-0026](../../../adr/0026-discovery-gate.md) (discovery gate).
> **Registry format:** [ADR-0046](../../../adr/0046-requirements-exceptions-testcase-registry.md).
> **Solution:** [`scripts/lib/discovery-authored.mjs`](../../../scripts/lib/discovery-authored.mjs) (pure scanner) wired into [`scripts/lib/doctor.mjs`](../../../scripts/lib/doctor.mjs) `checkDiscoveryAuthored()` (soft check).
> **Validated by:** [`scripts/lib/discovery-authored.test.mjs`](../../../scripts/lib/discovery-authored.test.mjs) (5 cases; the false-negative case scans the REAL `discover.mjs` output, not synthetic strings — critic 2026-07-15). Cases: [`BR_08.cases.mjs`](./BR_08.cases.mjs).
> **Live view:** `loom doctor` → `discovery-authored (warn)`.

The ask: **a stamped-but-unauthored discovery doc must not pass as "done."** `scripts/discover.*` stamps template content; `doctor` sees the file exists and the discovery gate passes while the requirements are boilerplate — the exact silent-degradation that broke prior dogfoods. This soft check flags two **structural** markers `discover.mjs` actually renders — the italic example cell `*(e.g., …)*` (FR-01 / RISK-01 / OQ-01 / out-of-scope) and empty template rows `| FR-02 | | … |` — matched against the real generator output (verified by running it), not the lesson's shorthand prose. `quick-scan.md` is **excluded** (no reliable tell — its `you`/`TBD` defaults are indistinguishable from a legit solo-project answer; it is explicitly non-authoritative). **Guarded** so it never fires on `loom-template` (only `discovery/README.md`) nor on the realistic post-bootstrap state (only `quick-scan.md` → "skipped, full discovery not started").

## Known limitations (tracked, not hidden)

- **Tell-based, not semantic (SE):** the check detects the template's *specific* placeholder strings, not "is this requirement meaningful?" An author who deletes the tells but writes shallow content passes. It closes the *silent-skip* trap (scaffolding treated as done), not the deeper "are these good requirements?" question — that is the critic's job (ADR-0026), which the lesson recommends making a first-class discovery step.
- **Soft, not hard (by design):** per the lesson's recommendation #1 ("a doctor *soft-check*"), this warns rather than blocks — a project may legitimately be mid-discovery. Tying the deploy/PR gate to authored-ness (recommendation #3) is a follow-on.
