# BR_09 — Cold-start bootstrap fixes (louder advisory + visible marker)

> **Requirement source:** handoff 2026-07-15 "Pending work" #2 (Phase-1b reliability) + lesson [`2026-07-10-first-governed-session-cold-start.md`](../../../lessons-learned/2026-07-10-first-governed-session-cold-start.md). Relates [ADR-0020](../../../adr/0020-runtime-discovery.md) + [ADR-0038](../../../adr/0038-hook-capture-gap-detection.md).
> **Registry format:** [ADR-0046](../../../adr/0046-requirements-exceptions-testcase-registry.md).
> **Solution:** [`scripts/hooks/_lib.mjs`](../../../scripts/hooks/_lib.mjs) (`COLD_START_ADVISORY` + `bootstrappedThisSessionPayload`) surfaced by [`scripts/hooks/session-start.mjs`](../../../scripts/hooks/session-start.mjs) (marker + advisory) and the [`scripts/bootstrap.sh`](../../../scripts/bootstrap.sh) / [`.ps1`](../../../scripts/bootstrap.ps1) banners; visible via [`observatory/lib/aggregator.mjs`](../../../observatory/lib/aggregator.mjs) (`bootstrapped_this_session` handler + activity feed).
> **Validated by:** [`scripts/lib/cold-start.test.mjs`](../../../scripts/lib/cold-start.test.mjs) (6 cases). Cases: [`BR_09.cases.mjs`](./BR_09.cases.mjs).
> **Live view:** Observatory → activity feed (`cold-start`) + `state.compliance.bootstrapped_this_session`.

The ask: **make the cold-start gap impossible to miss.** When Loom is bootstrapped mid-session (or a session starts before `.claude/` existed), the founding session's hooks + subagents aren't registered — it can't self-govern, and a careless run produces a project that *looks* bootstrapped while its audit trail is empty. The existing RESTART banner says "subagents not invokable"; this adds the two workarounds the lesson calls out (ADR-0034 path 2b; hand-authored audit) and a machine-checkable `bootstrapped_this_session` marker so the gap is **visible in the log**, not inferred.

## Known limitations (tracked, not hidden)

- **Both cold-start paths emit the marker (critic re-review 2026-07-15):** the true hookless founding session (Loom bootstrapped mid-session) never fires `session-start.mjs`, and once bootstrap stamps the placeholders `findPlaceholders()` returns `[]` forever — so the hook-side marker alone would NEVER fire for that scenario. Fixed by having `bootstrap.{sh,ps1}` call [`scripts/lib/mark-bootstrapped.mjs`](../../../scripts/lib/mark-bootstrapped.mjs) directly (runs in the shell regardless of hook registration) → the marker is persisted + Observatory-visible for both paths: hook-side (auto-bootstrap, `source: session-start`) and script-side (manual bootstrap, `source: bootstrap-script`). The banner is the human-visible layer; the marker is the machine-checkable one.
- **`stamped` reflects actual success (critic):** the hook-side marker sets `stamped: result?.status === 0` — a failed/skipped auto-bootstrap leaves placeholders, so it does NOT falsely claim the project was stamped. The advisory still fires either way.
- **Advisory, not enforcement (by design):** this surfaces the gap; it does not BLOCK an ungoverned session (that would be Phase-1b enforcement, which ADR-0054 gates on constitution-service). Consent-based + escapable by construction.
